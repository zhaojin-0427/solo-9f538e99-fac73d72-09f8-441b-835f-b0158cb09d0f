# 旧票款入仓校对（Flask + SQLite）

扫描得到的旧票款清单存在 OCR 金额识别不准的问题：每笔票款保留 1～3 个候选
金额，需要结合按窗口、按售票日的两套纸面合计，逐笔校对出唯一正确金额后才能
入仓。本应用用约束求解（CSP）在网页上逐笔列出**当前仍可行**的候选金额，
复核员确认一笔即重算一次；每笔都唯一后，可选择任一已上传批次一次性入仓并
保留入仓台账。

## 功能与约束

- 每批最多 24 笔；金额均为 `0～1 000 000` 的整数分。
- 上传三个 UTF-8 CSV：
  - 票款清单：`票号,窗口,售票日,候选金额1[,候选金额2,候选金额3]`
    （兼容英文表头 `ticket_no,window,sale_date,candidate1..3`）
  - 窗口合计：`窗口,合计`
  - 售票日合计：`售票日,合计`
- 求解器不枚举整批填法，只通过带记忆化的回溯搜索 + 分组后缀可达集合剪枝，
  判定每个候选值是否出现在**至少一个同时满足两套合计的完整解**中。
- 复核员提交一笔确认时，系统把该笔候选域收缩为确认值并与全部最新已确认金额
  一起重新求解；无解则整笔事务回滚，提示冲突并保留原有确认。
- 只有每笔都只剩一个可行金额时才允许下载校对结果 CSV
  （列：票号、窗口、售票日、金额，金额单位：分）。
- 所有确认/撤销动作写入 `confirmations` 审计表。

## 数仓入仓

校对页底部提供“入仓所选批次”入口，复核员可从**任一已上传批次**中选择提交。
入仓判定同时满足四类约束：

1. 本批原候选金额；
2. 当前人工确认金额；
3. 两套纸面合计（窗口 + 售票日）；
4. 同票已入仓金额。

**同票定义**：同一天、同一窗口下票号相同的记录算同一张票。已入仓的票再次
出现在重扫批次中时，直接沿用已入仓金额作为该笔的唯一取值并跳过写入，因此
重扫的票只计入一次，已入仓金额和原校对记录都会保留。

只有当前求解下每笔都只剩一个可行金额时，才在**一个写事务内**一次写入本批
尚未入仓的票；无解或金额不唯一时网页说明原因（列出冲突/仍多值的票号），
整批不写。

### 并发

- 求解在不持写锁的情况下进行（SQLite WAL + 写事务 `BEGIN IMMEDIATE`），
  求解期间仍可确认、撤销或让不重叠的批次入仓。
- 求解快照会记录“本批每笔的候选/确认 + 与本批同票的入仓金额”。写入前再次
  比对：若求解所依据的本批确认或同票入仓情况有变，则回滚并按最新状态重判，
  再写入或拒绝。与无关票的入仓不会改变快照，因此不会触发重算。
- `warehouse_records` 对 `(票号, 窗口, 售票日)` 建唯一约束，即使多进程同时
  提交也只会有一条记录；冲突时按最新状态重判。

### 累计明细

页面底部“入仓累计明细”可按售票日查询已入仓票款（票号/窗口/金额/来源批次/
入仓时间）与该日合计，并给出各售票日累计汇总；每张票只计一次。

## 目录

```
app/            Flask 应用（solver 求解器 / parsing 校验 / db 持久化 / services 编排）
tests/          pytest 用例（求解器、CSV 校验、HTTP 全流程、入仓与并发）
sample_data/    可直接上传的示例 CSV（含两批同票的重扫示例）
wsgi.py         gunicorn 入口
Dockerfile / docker-compose.yml
```

示例数据：`entries_sample.csv` + `window_totals_sample.csv` +
`date_totals_sample.csv` 为第一批；`entries_rescan_sample.csv` +
`window_totals_rescan_sample.csv` + `date_totals_rescan_sample.csv` 为重扫批
（含与第一批同票的 T003、T005）。

## Docker Compose 启动

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
```

SQLite 数据保存在命名卷 `recon-data`（容器内 `/data/recon.sqlite3`）。
生产环境请通过环境变量 `RECON_SECRET_KEY` 覆盖默认密钥。

## 本地运行（无 Docker 时）

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
python wsgi.py            # http://localhost:8000
```

## 自测

```bash
pip install -r requirements.txt pytest
python -m pytest tests/ -q
```

## 关键设计说明

- **分组后缀可达集合**：对每个窗口/售票日分组，预计算“剩余 k 个成员能凑出的
  金额集合”，DFS 赋值后用 `目标-已用` 是否在集合内做前向检查；集合过大时
  自动退化为 min/max 剪枝，并有搜索状态数上限保护。
- **确认即收缩域**：已确认笔的候选域变为单值，重算结果写回 `entries.feasible`；
  同票已入仓的笔也收缩为已入仓金额，页面展示的可行值与入仓判定一致。
- **事务安全**：确认、撤销、建批、入仓均在单个 SQLite 事务内完成，冲突回滚
  不留痕。入仓台账只追加，不修改也不删除。
- **写入前重判**：入仓用状态指纹做乐观并发校验，避免拿求解时的旧状态写入。
